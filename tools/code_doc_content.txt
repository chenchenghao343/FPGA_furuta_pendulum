#H2 1.1 一句话概括这个设计在做什么
#C
上电后：
  ① 50MHz 时钟进来，复位同步释放
  ② ADC 每 3ms 输出一个「摆杆角度」（3ms 窗口 16 点平均，控制率 333.33 Hz）
  ③ 编码器每拍输出「摆臂位置」与增量
  ④ 角度做差分得到「角速度」（含 4 阶滑动平均滤波）
  ⑤ 流水线 PID 用「角度偏差 + 角速度 + 摆臂位置偏差 + 位置增量」
     算出控制量 u（5 级流水线，延迟 5 拍 = 100ns）
  ⑥ 状态机决定：空闲输出 0 / 起摆用能量泵 / 平衡用 PID
  ⑦ 控制量送 motor_drv → PWM + 方向 → TB6612 → 电机
  ⑧ 同时：串口每约 20ms 上报一帧遥测，并接收调参命令
#/C

【通路①】控制输出

#H2 2.2 一个控制周期内发生了什么（时间线）
#P 控制节拍 tick 由 angle_adc 产生，周期 = 150000 / 50MHz = 3.0 ms（控制率 333.33 Hz）。这 3 ms 里：
#T 时刻（时钟拍）|发生什么|涉及文件
#R 0|angle_adc 窗口满 3 ms（16 点求和后 >>4），输出 angle_raw，拉高 angle_vld（= tick）|angle_adc.v
#R 0|同一拍：qep_encoder 持续更新 pos_raw/pos_rel（它每拍都在跑）|qep_encoder.v
#R 0|limit_prot 在 tick 上判越界；ctrl_fsm 在 tick 上判状态迁移|limit_prot.v / ctrl_fsm.v
#R 0|ang_deriv 在 tick 上做差分 + 滑动平均，输出 dtheta / dx|ang_deriv.v
#R 0|pos_ctrl 在 tick 上限速逼近参考，输出 err_x|pos_ctrl.v
#R 0|swing_pump 在 tick 上算能量泵输出与捕获标志|swing_pump.v
#R 1~5|pid_pipeline 的 5 级流水线依次推进，第 5 拍输出新 u_ctrl|pid_pipeline.v
#R 1~65535|流水线持续每拍产出（输入保持，输出保持稳定值）|pid_pipeline.v
#R 每拍|motor_drv 的 10kHz PWM 计数器自由运行，比较值随 u_ctrl 变化|motor_drv.v
#R 每约20ms|uart_link 发一帧 28 字节遥测；uart_rx 随时接收调参字符|uart_link.v
#/T
#N ★ 关键理解：PID 流水线是自由运行的（每个 50MHz 时钟都在推进），而误差每个控制周期才更新一次。所以「N 级 = N 拍」里的「拍」是 50MHz 时钟拍（100ns），不是控制周期（1.31ms）。这一点很容易误解。

#H2 4.1 pid_pipeline.v —— 核心：5 级硬件流水线 PID
#P 职责：实现 u = Kp·e + Kd·Δθ + Ki·Σe + Kpx·ex + Kdx·Δx，全部在硬件里流水完成。
#H3 关键技术 1：5 级分级结构
#S pipe_s1
#P S1 把输入与系数一并锁存。系数同拍锁存很重要：调参瞬间不会出现「P 用新系数、D 用旧系数」的控制量跳变。
#S pipe_s2s3
#P S2 做 P 项乘法（两个独立 DSP），同时把 D/I 需要的操作数透传到 S2 寄存器；S3 做 D 项乘法并更新积分累加器，另外把 P 项也打一拍。
#S pipe_s4s5
#P S4 是加法树（5 个输入全部来自 S3 寄存器，严格同拍）；S5 做一次算术右移完成 Q10 反标定。
#H3 关键技术 2：分级对齐（曾经的真实缺陷）
#N ★ 最初版本 S4 直接写 s4_sum_a <= s2_p_term + s3_d_term，但这两个信号分别在第 2 级和第 3 级产生，相差整整一级。输入突变时会把「新的 P 项」和「旧的 D 项」相加。修法就是在 S3 加 s3_p_term / s3_px_term 两个寄存器把 P 项延后一级。
#H3 关键技术 3：三重抗饱和
#S pipe_antiwindup
#P 输出已饱和且积分增量与饱和方向相同时冻结积分（继续积分只会加深饱和）；反向时自动解冻，保证能退出饱和。另有积分累加器硬限幅与输出限幅。
#H3 关键技术 4：移位代替除法
#S pipe_shift
#N ★ 必须用算术右移 >>>。用除号会综合出除法器，而且对负数向零取整，行为与算术右移不同（-3/2 = -1，而 -3 算术右移 1 位 = -2）。
#H3 延迟核算
#T 项|数值
#R 流水线级数|N = 5
#R 流水线延迟|5 × 20ns = 100 ns（@50MHz）
#R 控制周期|3.0 ms（外环 30 ms）
#R 环路群延迟|3.0 ms + 0.0001 ms ≈ 3.0001 ms（另有微分 4 点滑动平均 4.5 ms）
#R 流水线贡献占比|100ns / 3.0ms ≈ 0.0033%
#R 10Hz 处相位损失|arctan(2π·10·100ns) ≈ 0.036°（可忽略）
#/T
#N P/D/I 三项穿越的级数完全相同，因此相对相位被严格保持，不存在「P 快 D 慢」造成的等效微分相位误差，无需额外补偿。
#H2 4.2 angle_adc.v —— ADC 采集与量程标定
#P 职责：驱动 3PA1030（25MHz 采样时钟 + 低有效输出使能），把 10bit 并行数据扩到 12bit，做 2^16 点平均，并产生整个控制环的节拍。
#S adc_avg
#B 65,536 × 4095 = 268,369,920 < 2^28，所以 28 位累加器刚好不溢出
#B 取 sum >> 4 等于精确除以 16，不需要除法器
#B 输出频率 = 50MHz / 150000 = 333.33 Hz，周期 3.0 ms
#N ★ 采样计数器必须独立（win_cnt）：累加和的低位会随加数进位，不是干净递增，判满会漏判。v6.2 起改为单计数器 + 端点对齐（out_pulse / step_pulse 结构互斥）。
#H2 4.3 qep_encoder.v —— 正交编码 4 倍频
#P 职责：把编码器 A/B 两相方波解码成位置计数与增量。
#S qep_case
#B 用「上一次状态, 本次状态」组成 4bit 索引查表，8 种合法跳变 ±1，非法跳变（两位同时翻转）保持不变
#B A/B 每个边沿都计数 = 4 倍频；标定 1067 counts/圈
#B pos_rel = pos_raw − 10000，用同宽回绕减法，有符号解释即为相对位置
#H2 4.4 motor_drv.v —— PWM 与方向
#P 职责：把有符号控制量变成 TB6612FNG 需要的 PWM + 方向信号。
#S motor_dir
#B PWM 载波 50MHz/5000 = 10 kHz
#B 取绝对值前先符号扩展到 17bit，避免 u_ctrl = −32768 时取负溢出
#B 死区（|u| ≤ 20）内强制停机，防止零速附近抖动
#B 复位期间 pwm 被 rst_n 门控为 0，避免上电瞬间误驱动电机
#H2 4.5 uart_rx.v —— 串口接收
#P 职责：9600 8N1 接收，位中点采样，带停止位校验。
#S rx_start
#N ★ 这是本工程抓出的一个真实缺陷。原来直接用下降沿同时驱动「置 work_en」和「清 bit_idx」，而数据位里的下降沿也会被当成起始位。以 0x5A 为例，D2/D5/D7 处都有下降沿，帧收到一半 bit_idx 被清零，整帧作废。改为只在空闲（work_en=0）时接受下降沿。
#S rx_mid
#S rx_shift
#B bit 索引：0=起始位，1..8=D0..D7，9=停止位
#B 停止位不是 1 时丢弃该字节、不输出 po_flag，并输出 frame_err 脉冲
#H2 4.6 uart_tx.v —— 串口发送
#S tx_tick
#N ★ 原实现把 bit_tick 写成寄存器，比 baud_cnt 归零晚一拍，导致每一位都被拉长 1 拍（5209 而非 5208），整帧变成 52090 拍，与注释写的 52080 矛盾。改为组合 tick 后恢复正常。
#S tx_latch
#N ★ 原实现直接用端口 pi_data 驱动每一位输出，等于没有真正消费 pi_flag 所声明的数据。传输中途改 pi_data 会污染正在发送的帧（实测：发 0x55 到一半注入 0xAA，本帧发出的就是 0xAA）。改为启动那拍锁存整字节。
#H2 4.7 pid_tuner.v —— 串口在线调参
#P 职责：解析单字符命令，维护 6 个系数（倾角环 Q10 + 位置环 Q12）。★ v7.2：外环积分删除，原来的积分档位 i_shift 与 'T'/'t' 命令一并移除。
#S tuner_up
#S tuner_neg
#S tuner_sat
#T 命令|作用|备注
#R 1..5|选 KP/KI/KD/位置P/位置D|
#R > <|±12.5%（保号）|负数同样正确：−1000 的 +12.5% = −1125
#R * /|×2 / ÷2（保号）|除法用算术右移而非除号
#R +|加 64|★ 破解「0 是乘法不动点」的死锁
#R -|取反|★ 极性可现场翻转，不必重综合
#R P|翻转起摆极性|★ 取代编译期参数 PUMP_POLARITY
#R R / S|运行开关 / 遥测开关|
#R U / D|记录直立 / 下垂参考|
#/T
#N ★ 「+」和「-」是后来补的。原来的五条命令全是乘法型，有两个死角：① 系数降到 0 后 0 乘以任何数仍是 0，永远调不出来；② 全部保号，无法翻转极性。这两点会让「免反复综合」变成空话。
#H2 4.8 swing_pump.v —— 起摆能量泵
#P 职责：摆杆下垂时把它泵到直立附近。
#S pump_cos
#S pump_dir
#P 物理依据：对摆臂施加线加速度 a 时，摆杆能量变化率 dE/dt = −m·l·a·θ̇·cosθ。只要令 a 与 sign(θ̇·cosθ) 反向，就能保证持续注入能量。
#N ★ 这里踩过一次有符号/无符号陷阱：写成 (13'sd1024 − phi_abs[12:0]) < −13'sd1024 时，部分选择 phi_abs[12:0] 是无符号的，导致整个比较退化成无符号，−1024 被当成 7168，条件恒真 → cos 恒为 −1024 → 起摆方向永久反向。上板只会表现为「起摆不好使」，极易误判成机械摩擦。修法是先扩位成 17bit 有符号再比较。

#H1 第 5 章  关键技术深挖
#H2 5.1 为什么必须是硬件流水线而不是多周期串行
#T 方案|延迟|吞吐率|是否满足赛题
#R 5 级流水线（本设计）|5 拍 = 100ns|1 个控制量/拍|满足：每拍接收新误差、每拍产出新控制量
#R 单个乘法器串行复用|5 拍 = 100ns|1 个控制量/5 拍|不满足：吞吐率只有 1/5
#R 纯组合逻辑|1 个长乘法加法链|1 个/拍|不满足：关键路径过长，50MHz 下时序不收敛
#/T
#P 实测印证：布局布线后的静态时序分析显示，最差路径并不在 PID 流水线上（而在 swing_pump 的 cos 近似 + 乘法链），说明流水线确实起到了分割关键路径的作用。实际 Fmax 77.4MHz，对 50MHz 有 35% 余量。
#H2 5.2 Q10 有符号定点为什么够用
#T 信号|范围|位宽|说明
#R 角度偏差 e|±2048|16bit 有符号|12bit ADC(0~4095) 减参考后
#R 增益系数|0.001 ~ 32.0|16bit 有符号 Q10|1.0 = 1024，最大 32767
#R 单项乘积|16×16|32bit 有符号|用 32bit wire 承接避免截断
#R 积分累加器|限幅 ±2^22|32bit 有符号|带硬限幅，不会回绕
#R 级间求和|5 项之和|36bit 有符号|留 1bit 余量
#/T
#N 注意：所有项都在「Q10 乘积域」内相加，只在 S5 做一次算术右移，避免逐级移位带来的累积截断误差。
#H2 5.3 起摆能量泵的物理推导
#C
E(θ,θ̇) = ½·J·θ̇² + m·g·l·(cosθ − 1)    以倒立静止为零势能点

对摆臂施加水平加速度 a：
    dE/dt = −m·l·a·θ̇·cosθ

令 a 与 sign(θ̇·cosθ) 反向  ⇒  dE/dt > 0  ⇒  持续注入能量
摆杆能量从 −2mgl（下垂静止）升到 0（倒立静止）即完成起摆。
#/C
#B 方向会随 cosθ 变号而翻转 —— 这正是起摆时摆杆来回增幅的物理来源
#B 不需要真的算能量数值，方向只依赖符号，所以只要 cos 的符号对即可
#B 死区踢摆：摆杆静止时角速度≈0，符号不定，用固定方向脉冲打破对称性
#H2 5.4 异步输入的处理策略
#T 输入|同步级数|原因
#R 按键|2 级 + 20ms 计数|机械抖动，且人手动作慢
#R 编码器 A/B|2 级 + 四相查表|电机旋转时边沿密集，必须抗亚稳态
#R 串口 RX|3 级 + 下降沿检测|起始位识别需要边沿，多一级更稳
#R 复位 rst_n|clk_mgr 同步释放|异步复位端直接释放会产生恢复/去除时间违例
#R ADC 并行数据|不用同步|同域，由 FPGA 输出的 adc_clk 驱动，且做了 3ms 窗口 16 点平均
#/T
#H2 5.5 串口协议的实现要点
#B 帧格式：AA 55 + w0..w11（24 字节数据）+ 0D 0A，共 28 字节，多字节字段大端序
#B 字节间隔 ≥ 一个字节传输时间（52080 拍），保证 9600 下不粘连
#B 位宽严格 5208 拍（= 50MHz/9600 取整），整帧 52080 拍
#B 上位机按帧头 AA 55 滑动重同步，丢字节或错位都能自动恢复

#H1 第 6 章  可观测性设计（为什么好调试）
#P 这个设计在「能看见内部状态」上做了不少工作，这是上板调试效率的关键。
#T 手段|内容|用途
#R 4 个 LED|心跳 / 运行中 / 已平衡 / 告警（限位或饱和或串口帧错）|不接电脑也能一眼看出状态

#R 系数面板|按 G 显示 5 个系数当前推算值|解决遥测帧无系数回读的盲区

#N ★ 设计原则：任何「只有上板才知道」的量，都要做成不必重综合就能改的形式。三处极性、增益、参考点标定都符合这一条——串口命令 + 参数 + 按键覆盖了绝大多数现场调试需求。
